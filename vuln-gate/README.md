# VulnGate — Execution-Based Vulnerability Verification

> *"Floods of AI-generated bug reports overwhelm maintainers. Demand execution-based proofs (PoC artifacts like ASan traces) before triaging."* — 2026 OSS Maintainer Burnout Analysis

**VulnGate** acts as a verification gate between vulnerability reports (especially AI-generated ones) and your triage queue. It rejects reports without execution-based proof of concept (PoC) artifacts — crash traces, ASan output, memory dumps, or reproducible test cases.

## The Problem

- AI agents generate thousands of speculative vulnerability reports
- Maintainers spend 70%+ of security time triaging false positives
- Without execution-based proof, AI-flagged vulns are often hallucinated
- CVE submissions without PoCs waste CNA resources

## Features

- **PoC Requirement Engine** — Rejects reports without minimum evidence (trace, crash dump, test case)
- **Trace Parsing** — Validates ASan, UBSan, MSan, Valgrind, gdb backtraces
- **Reproducibility Check** — Attempts to compile and run minimal PoC code in sandbox
- **Severity Adjustment** — Lowers severity for reports without execution-based proof
- **GitHub Issue Integration** — Automatically labels, comments, and closes insufficient reports
- **Weighted Scoring** — Scores reports based on evidence quality (trace > test > description-only)

## Quick Start

```yaml
# .github/workflows/vuln-gate.yml
name: VulnGate
on:
  issues:
    types: [opened, labeled]
jobs:
  gate:
    if: contains(github.event.issue.labels.*.name, 'security')
    runs-on: ubuntu-latest
    steps:
      - name: Verify PoC Evidence
        uses: ./vuln-gate/action
        with:
          github-token: ${{ secrets.GITHUB_TOKEN }}
          min-evidence: trace          # trace | test | description
          sandbox-execution: true       # try to compile & run PoC
          auto-close-below: 0.3         # auto-close reports scoring below this
```

## Evidence Scoring

| Evidence Type | Score | What It Requires |
|---|---|---|
| `crash-trace` | 1.0 | ASan, UBSan, Valgrind, or gdb backtrace |
| `poc-code` | 0.8 | Minimal reproducible test case in C/Python/Go/Rust |
| `screenshot` | 0.4 | Visual proof only |
| `description-only` | 0.1 | Text description with no artifacts |
| `ai-generated` | 0.05 | Flagged as AI-generated by classifier |

Reports scoring below `min-evidence` threshold are automatically returned to the reporter with a template requesting proper PoC artifacts.

## CLI Usage

```bash
# Validate a vulnerability report
python3 vuln-gate/vuln_gate.py validate \
  --report report.json \
  --min-score 0.5

# Extract traces from report body
python3 vuln-gate/vuln_gate.py extract \
  --body "ASAN: heap-buffer-overflow on address 0x..."

# Score a batch of CVE-like reports
python3 vuln-gate/vuln_gate.py batch \
  --input reports/ \
  --output scored-reports.json
```

## Example Report Format

```json
{
  "id": "VULN-2026-0715",
  "source": "github-issue",
  "ai_generated": true,
  "evidence": {
    "has_crash_trace": false,
    "has_poc_code": false,
    "has_screenshot": false,
    "trace_type": null,
    "trace_raw": ""
  },
  "score": 0.05,
  "verdict": "INSUFFICIENT-EVIDENCE",
  "message": "This report lacks execution-based PoC artifacts. Please provide: (1) ASan/UBSan trace, (2) minimal reproducible test case, or (3) Valgrind output."
}
```
